# Google Sheets Discord Notification GAS

Googleスプレッドシートの購入申請シートに入力・更新された内容を検知し、Discord Webhookへ通知するGoogle Apps Scriptです。

新規追加時だけでなく、既存データの金額修正やステータス変更時にも「更新通知」を送信します。
Discord側のレート制限（429エラーなど）や一時的な送信失敗に備えて、複数行を1つのメッセージにまとめる「バッチ通知」機能や、スプレッドシート上の管理列を使った再送（バックオフ）機能を備えています。

---

## 主な機能

- Googleスプレッドシートの特定シートを監視
- **【新規/更新の自動判別】** A列の入力状況と編集履歴から「新規データ」と「データ更新」を厳密に判別
- A/C/D列（必須列）、またはG/H/I列（追加監視列）の編集を検知して通知対象とする
- 入力完了後すぐには通知せず、3分後に通知を試行（入力途中の連続通知を防止）
- **【バッチ通知】** 複数行の通知が重なった場合、Discordの文字数制限やレート制限を回避するため最大5件ずつまとめて送信
- Discord Webhookへの通知とロールメンション対応
- DiscordのHTTP 429やCloudflare error code 1015への対応
- 長時間 `Utilities.sleep()` せず、次回通知試行時刻をシートに書いて後で再試行（エラー時も新規/更新ステータスを保持）
- 通知状態をスプレッドシート上の **J/K/L列** で管理
- Webhook URL、対象シート名、ロールIDをスクリプトプロパティで管理し、秘密情報をコードに含めない構成
- デバッグ用関数を同梱

---

## 想定するシート構成

対象シート名はスクリプトプロパティ `SHEET_NAME` で指定します。
本スクリプトは以下の列構成を前提として動作します。

| 列番号 | 列記号 | 項目名 | 用途・制約 |
| :---: | :---: | :--- | :--- |
| 1 | **A** | **申請者** | **[必須]** この列が空欄から入力された瞬間を「新規」と判定します。 |
| 2 | B | （任意） | 監視対象外 |
| 3 | **C** | **内容** | **[必須]** 通知メッセージに反映されます。 |
| 4 | **D** | **予定金額** | **[必須]** 通知メッセージに反映されます。 |
| 5-6 | E-F | （任意） | 監視対象外 |
| 7 | **G** | **領収書受領** | チェックボックス専用。編集すると「更新待機」になります。 |
| 8 | **H** | **実際に払った金額** | 編集すると「更新待機」になります。 |
| 9 | **I** | **コメント** | 編集すると「更新待機」になります。 |
| 10 | **J** | **Discord通知** | **[GAS管理列]** 通知ステータス（通知済/新規待機/更新待機）を記録。 |
| 11 | **K** | **通知エラー** | **[GAS管理列]** 送信失敗時のエラー内容を記録。 |
| 12 | **L** | **次回通知試行時刻** | **[GAS管理列]** 次に通知を試みる時刻を記録。 |

> **※注意**：A列が空欄の行は、他の列（G〜I列など）を編集してもGASは完全に無視します。

---

## 通知管理列

### J列: Discord通知

GASが現在の行の通知ステータスを書き込みます。

- `新規待機`: 新しくA列に入力が行われ、通知を待っている状態
- `更新待機`: すでに「通知済」の行に対して、A/C/D/G/H/I列のいずれかが編集された状態
- `通知済`: Discordへの送信が完了した状態

J列が空欄の行は未処理扱いとなり、A列への新規入力が行われると自動的にフラグが立ちます。

### K列: 通知エラー

Discord通知に失敗した場合、最後のエラー内容を記録します。

例:
```text
HTTP 429: error code: 1015
```
スクリプトプロパティ未設定など、GAS側の例外もK列に記録されます。エラー発生時でもJ列の「新規/更新」ステータスは維持されます。

### L列: 次回通知試行時刻

次にDiscord通知を試す時刻を記録します。

編集が行われると、まず現在時刻の「3分後」が設定されます。
Discord通知に失敗した場合は、Discord側の `retry_after` またはデフォルトの再試行間隔に基づいて次回試行時刻が自動で延長されます。

## 通知の流れ

```text
ユーザーが監視対象列（A/C/D/G/H/I）を編集
↓
onEditトリガーが発火
↓
A列が空欄の場合は無視して終了。入力されていればJ列に「新規待機」または「更新待機」を書き込み
↓
A/C/D列がすべて入力済みか確認し、L列に「現在時刻 + 3分」を設定
↓
時間主導トリガーが定期実行（1分ごと）
↓
L列の時刻を過ぎており、かつJ列が「通知済」でない行を抽出
↓
複数行ある場合は1つのメッセージにまとめ（最大5件）、Discordへ送信
↓
成功したら対象行のJ列に「通知済」、K/L列をクリア
↓
失敗したらK列にエラー、L列に次回試行時刻を書き込み（J列は維持）
```

## 必要なスクリプトプロパティ

Apps Scriptの「プロジェクトの設定」から、以下のスクリプトプロパティを設定してください。

| プロパティ名 | 内容 | 例 |
|---|---|---|
| `DISCORD_WEBHOOK_URL` | Discord Webhook URL | `https://discord.com/api/webhooks/...` |
| `SHEET_NAME` | 対象シート名 | `購入申請シート` |
| `MENTION_ROLE_ID` | DiscordロールID | `123456789012345678` |

`SHEET_NAME` と `MENTION_ROLE_ID` はコードに直接書かず、スクリプトプロパティから取得します。

---

## Discord Webhook URLの設定

コード内の `setDiscordWebhookUrl()` を使って設定する場合は、以下の部分を実際のWebhook URLに変更してから実行します。

```javascript
function setDiscordWebhookUrl() {
  const webhookUrl = 'https://discord.com/api/webhooks/XXXXXXXX/XXXXXXXX';

  PropertiesService
    .getScriptProperties()
    .setProperty(CONFIG.PROPERTY_KEYS.DISCORD_WEBHOOK_URL, webhookUrl);
}
```
Webhook URLは公開リポジトリに直接コミットしないでください。

## セットアップ手順

### 1. Apps Scriptにコードを貼り付ける
Googleスプレッドシートを開き、以下からApps Scriptエディタを開きます。
`拡張機能 → Apps Script`
`Code.gs` の内容を貼り付けて保存します。

### 2. スクリプトプロパティを設定する
Apps Script画面で以下を開き、プロパティを追加します。
`プロジェクトの設定 → スクリプト プロパティ`

### 3. 設定確認
以下の関数を実行し、スクリプトプロパティが正しく設定されているか確認します。
```javascript
checkScriptProperties()
```

### 4. 編集トリガーを作成
以下の関数を1回実行します（初回のアカウント認証が必要です）。
```javascript
setupTrigger()
```
この関数は、スプレッドシート編集時に `notifyDiscordOnEdit(e)` を実行するインストール型トリガーを作成します。

### 5. 時間主導トリガーを作成
以下の関数を1回実行します。
```javascript
setupTimeTrigger()
```
1分ごとに `processPendingDiscordNotifications()` を実行する時間主導トリガーを作成します。1分ごとの作成が不安定な場合は、代替として `setupTimeTriggerEvery5Minutes()` を実行してください。

### 6. テスト通知
以下の関数を実行します。
```javascript
testDiscordNotification()
```
Discordに「✅ Google Apps Scriptからのテスト通知です。」と届けば設定は成功です。

## J/K/L列の保護について

J列・K列・L列はGASがシステム管理に利用する列です。
ユーザーが手動で変更すると、通知漏れや二重通知の原因になります。
そのため、Googleスプレッドシート側で **J〜L列を保護する** ことを強く推奨します。

```text
保護範囲: J:L
編集可能ユーザー: スクリプト管理者のみ
```
※GASはトリガー作成者の権限で実行されるため、トリガー作成者はJ/K/L列を編集できる必要があります。一般ユーザーが編集するG・H・I列は保護の対象外としてください。

## Discord通知内容

通知メッセージにはC列（内容）とD列（予定金額）が自動で含まれます。

**【単独通知の場合】**
```text
📢 新しいデータが追加されました （※更新時は「📢 データが更新されました」）
申請者: {{value}}
内容: {{cValue}}
予定金額: {{dValue}}
日時: {{time}}
{{url}}
```

**【バッチ通知（まとめ送信）の場合】**
複数行が同時に通知対象となった場合、以下のように1つのメッセージとしてまとまります。
```text
📢 複数件のデータが追加・更新されました (計 2件)

【新規データ】
申請者: 山田
内容: 備品購入
予定金額: 5000
日時: 2026/06/16 12:34:56
https://docs.google.com/...

---

【データ更新】
申請者: 佐藤
内容: 書籍代
予定金額: 3000
日時: 2026/06/16 12:35:10
https://docs.google.com/...
```
通知の先頭にはDiscordロールメンションが付加されます。

---

## 429 / 1015エラーへの対応

Discord側で一時的なレート制限が発生すると、HTTP 429 や Cloudflare error code 1015 が返ることがあります。
このGASでは、長時間待機せずK列にエラー内容、L列に次回通知試行時刻を書き込みます。
また、エラー発生時のステータス（新規・更新）はJ列に保持されるため、再試行時も正しいフォーマットで送信されます。

## デバッグ手順

### トリガー確認
```javascript
debugListTriggers()
```

### 未通知行の判定確認
Discord通知は送らず、各行の判定状態だけをログに出します。
```javascript
debugPendingNotificationRows()
```
ログ例: `row=5 | J="新規待機" | K="" | L_parsed="2026/06/16 12:00:00" | due=true`

### J列へGASから書けるか確認
```javascript
debugWriteNotificationStatusForRow()
```
実行前にコード内の `const row = 8;` を対象行に変更してください。

### 旧方式から移行する場合
旧仕様（通知済み状態をプロパティで管理）のデータを削除する場合は以下を実行します。
```javascript
cleanupOldNotificationProperties()
```

## 主な関数

| 関数名 | 役割 |
|---|---|
| `setDiscordWebhookUrl()` | Discord Webhook URLをスクリプトプロパティに保存 |
| `checkScriptProperties()` | 必須スクリプトプロパティの確認 |
| `setupTrigger()` | 編集時トリガーを作成 |
| `setupTimeTrigger()` | 1分ごとの時間主導トリガーを作成 |
| `notifyDiscordOnEdit(e)` | 編集時に新規・更新を判定し予定時刻を設定 |
| `processPendingDiscordNotifications()` | 未通知行を抽出・バッチ化してDiscordへ通知 |
| `testDiscordNotification()` | Discord Webhookのテスト通知 |

---

## 注意事項

- Webhook URLは絶対に公開リポジトリへコミットしないでください。
- J/K/L列はGAS管理列として保護してください。
- A列が空欄の行は監視対象から外れます。
- 通知は即時ではなく、入力完了後「約3分以降」の定期実行タイミングで行われます。
- トリガー作成者が対象スプレッドシートへの編集権限を失うと、GASが正常に動作しない可能性があります。
